Темп / Публикация серии
1. Распакуйте архив в постоянную приватную папку на Linux-сервере с Python 3.10+. Проверьте тексты и даты командой python3 publish.py. Эта команда только выводит план.
2. Разместите только дерево media/ на HTTPS-хостинге. Проверьте извне, что JPEG открываются без авторизации. PUBLIC_MEDIA_BASE — адрес каталога выше media, например https://example.com/releases. Остальные файлы, SQLite и секреты храните вне публичной директории.
3. В Meta настройте Instagram API with Instagram Login для своего профессионального аккаунта, роли аккаунта и разрешения instagram_business_basic и instagram_business_content_publish. Получите ID профессионального аккаунта и действующий токен. Руководство: https://developers.facebook.com/docs/instagram-platform/instagram-api-with-instagram-login/content-publishing/
4. На сервере передайте IG_ACCESS_TOKEN, IG_ACCOUNT_ID, PUBLIC_MEDIA_BASE и IG_API_VERSION (поддерживаемая версия из панели приложения, формат vNN.N) в переменные окружения процесса. Не добавляйте токен в сайт или публичный репозиторий. Обновляйте токен до истечения его срока.
5. После проверки включите вызов python3 /полный/путь/publish.py --publish раз в минуту через cron или systemd с этими переменными. Сервер должен работать в момент публикации. Даты в архиве указаны с московским смещением +03:00.
6. Программа отправляет только наступившие посты за последний час. Пропущенным назначьте новое время. При неопределённом результате отправки запись publishing блокирует повтор. Проверьте пост в Instagram и только потом вручную корректируйте состояние в publications.sqlite. Храните эту базу в одной рабочей папке между экспортами. Новая серия заменяет schedule.json: включайте в неё все ещё ожидающие посты. Не запускайте две копии на разных серверах для одного аккаунта.
